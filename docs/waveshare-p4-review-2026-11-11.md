## 已修复，待目标机验证

1. TCP JSON Lines 超长行：旧接收循环在溢出后可能越界写，跨 `recv` 还可能把同一条长消息的尾部当作新命令。现对超长或含 NUL 的行持续丢弃到换行，保留下一条消息；`send` 返回零时也会退出，避免发送循环空转。`firmware/tests/p4_tcp_line_framing_test.py` 对恰好上限、超长、不同分包及后续正常消息执行真实接收循环，并启用 ASan/UBSan。
2. Wi-Fi 配置数组支持完整 32 字节 SSID 和 64 字节密码；首次初始化和重新配网共用相同填充逻辑。回归测试覆盖上限与短字符串。
3. Wi-Fi 启动熔断改为调用可能崩溃的驱动之前持久化计数，成功返回后清零；模拟连续三次重启及恢复。
4. 开放网络的空密码可以从 NVS 重新加载，与配网时的输入规则一致。
5. Wi-Fi 语音推流在可选 NVS 命名空间不存在时回退到最近连接的主机；显式配置仍优先。该地址目前未经认证，仍受下述网络风险影响。
6. Wi-Fi PCM 推流在录音结束时关闭 socket、重置下一段的重试状态，使接收端能够开始下一段；异常断线的片段会丢弃，仍需实机验证。
7. TCP 请求和回复绑定连接代次；旧连接的队列请求被丢弃，回复不会流向新连接，发送失败由会话任务统一关闭，发送设置了 5 秒超时。描述符复用与失败关闭有主机回归测试。
8. PTT 的录音缓冲在处理结束前保持独占；忙碌时提示稍候，不切换到其他传输。Wi-Fi 掉线后仍保持该保护。超过约 16 秒容量时明确提示重录，不把截断内容当成完整录音。
9. PTT 请求覆盖 PC 服务启动及识别时间，避免静音预热额外延迟；WAV 上传支持网络短写。
10. 未显式配置识别地址时，PTT 使用当前 TCP 对端地址，录音期间冻结目标；没有活动连接时回退，不再使用固定内网 IP。已保存的用户地址仍然优先。
11. 桌面桥识别显式权限请求并保持忙碌，普通等待输入可继续语音；权限等待不会因 90 秒状态过期而自动放行。
12. 语音桥和固件的常规诊断日志不再打印识别文本，保留长度、耗时及状态。
13. Wi-Fi IP 与连接状态采用同一临界区快照；断线延迟重连移出系统事件循环，并合并重复重连任务。
14. PTT 每段使用独立随机标识；桌面端按设备来源 IP 和标识保存限量、限时、单次消费的目标快照。缺失或过期时拒绝识别投递，并容忍短暂的开始通知乱序。快照满时淘汰最旧项，避免短按累积使后续录音持续不可用；被淘汰的录音安全失败。此标识用于关联，不是身份认证。
15. 无线 PCM 的旧 HPA1 旁路仅把识别结果写入临时诊断文件，未接入桌面会话；普通音频现复用控制连接上的 `audio/begin`、`audio/chunk`、`audio/end` 与既有完整性校验，桌面端不再启动 8898 接收器，也不再写入该临时识别日志。本地按键 PTT 仍使用独立 WAV 上传，且不再发送不含 PCM 的普通音频会话。此前日志可能仍在磁盘，未经用户指示不删除。
16. 设备 HTTP 控制和桌面语音 HTTP 移除宽松 CORS，拒绝带 Origin 的跨站请求，并限定命令和音频的 Content-Type；保留无 Origin 的现有脚本。此项仅防浏览器跨站攻击，不是局域网认证。
17. 更新协议测试中会话卡片条件的旧断言，以匹配语音草稿期间隐藏会话卡片的现有行为。

## 高优先级待处理

### 局域网控制和语音端口缺少身份校验

- `firmware/main/pet_p4_tcp_bsp.c` 将完整 JSON Lines 协议监听于所有网卡的 3333 端口；`firmware/main/pet_p4_http_bsp.c` 的 80 端口提供协议行入队及屏幕截图。虽然已限制浏览器跨站请求，路由中仍未见连接级身份认证。
- `pc/src-tauri/src/device_voice_bridge.rs` 在所有网卡监听按键语音接口，接收音频并可向 Agent 的交互链路投递识别结果；旧 PCM 接收器不再启动。需要端到端验证身份、限制来源、明确配对和重连/换 IP 的用户流程，并考虑传输保密。此前已产生的日志仍可能包含旧文本；日志保留策略需要单独处理。仅限制 CORS 无法保护 TCP 客户端或其他 HTTP 客户端。
- 在完成认证前，设备和桌面端应只接入可信、隔离的网络；不要把端口暴露到互联网。认证涉及固件、桌面端和配网/恢复契约，不宜单方面加固定密码或静默破坏现有连接。

### 语音缓冲所有权与目标冻结

- 普通无线音频已改用现有控制连接的 PCM 会话协议；仍需以真实网络断连、拥塞和桌面实时对话进行端到端验证。完整性校验只能检测意外损坏，不验证发送者。
- PTT 现在在上一段处理结束前拒绝下一段并提示稍候；需要实机验证快速连按及失败恢复。512 KiB 上限约 16 秒；超出时设备提示重录，PC 端提示和具体显示效果仍需实机验证。
- PTT 当前可选择显式配置或活动 TCP 对端，但对端尚未认证；已有 NVS 显式地址仍优先，换网后若该地址已经过期需用户更新。需要与配对认证一起做实机验证。
- 本次按键实测期间曾额外建立 TCP 观察连接，以便设备获取 PC 地址；当前桌面调试版自动连接的是 USB，并未建立持续的 TCP 连接。没有显式地址和活动 TCP 对端时会回退原 USB 音频路径，不能把这次 PTT 成功推广为 USB 自动发现和重启后仍可用。
- 录音开始通知仍由网络异步发送：快照表示桌面端收到通知时的目标，而非严格证明按键瞬间的目标。桌面源码现将明确绑定的设备、Agent、会话 ID 和绑定代次与该录音快照关联，并在确认前及后台提交前复核；明确会话按原 ID 投递，不再自动选最近会话或创建新会话。自动跟随、缺少会话 ID、WorkBuddy 和 DeepSeek 的无线可见窗口路径因缺少可验证的会话身份而拒绝发送；USB 不受此限制。该无线改动尚未实机验收，录音标识和来源 IP 不能替代设备认证。
- 无线语音桥相关定向测试 12 项通过，覆盖未固定目标、会话切换和快照单次消费；异常或缺少明确 `ok` 的桥接响应不再被当作成功，新增回执测试通过。接受请求仅报告“已请求提交”，不声称已有送达回执。

### TCP 连接生命周期和协议完整性

- TCP 代次、发送锁和关闭所有权已加主机测试；仍需实机覆盖 Wi-Fi 断连、拥塞及重连中的事务状态，尤其是已开始执行但结果未知的写操作。
- TCP 接收不实现 USB 侧的 raw asset 模式，`pet_p4_main.c:1600` 的部分 debug/screenshot 特殊处理也只接受原有发送回调。TCP 通用 JSON 能运行不等于完整 USB 协议能力均可用；需要按操作逐项验证并如实声明能力。
- TCP 发送超时为 5 秒；单客户端监听和大量广播仍需实测中断恢复、背压与传输延迟。

### `waiting_user` 的语义边界

桥接层现将有明确权限请求标记的状态与普通等待输入分开，并保留权限等待直到新状态到达；桥接测试 231 项通过。上游若只发没有原因的 `waiting_user`，仍无法可靠判断是权限提示还是普通输入，需要上游提供明确事件并做实机联调。

### Wi-Fi 状态与恢复

连接状态和 IP 已同步读取，断线回调不再等待两秒；仍需实机验证 C6 断连、反复配网、任务创建失败与 NVS 故障。熔断依赖 NVS 计数能够成功写入，写入失败或初始化返回后异步崩溃仍需处理。

### 实机无线大流量与内部内存

2026-11-11 的实机复测发现 160 行 HTTP 截图流量可触发重启，串口分别捕获到 ESP-Hosted 1.4.7 的 `transport_drv_sta_tx` 发送缓冲分配断言，以及 `sdio_push_data_to_queue` 接收缓冲分配断言。设备启动后空闲内部 DMA 内存原约 9 KiB，压力下更少。构建时对锁定版本的两处源码生成经过哈希校验的副本，内存不足分别返回发送失败或丢弃剩余接收流，不改写组件缓存；版本变化时构建失败并要求复核。v3 将已有仅任务访问的状态模型放入 PSRAM，相关主机测试通过；实测空闲 DMA 约 104 KiB。完整 800 行截图分 5 次读取，两轮均成功且重启与故障计数未增加；另一次从 PSRAM 状态版本运行完整 OTA、切换分区并确认新镜像有效。仍须覆盖长时间网络压力、其他 SDIO 分配失败路径、Wi-Fi 重连及真实语音流，不能据此宣称所有内存耗尽情况已解决。

同次实机已确认设备 ID `p4-e8f60ae987e9`、ESP32-P4 v3.2 与 32 MiB Flash，OTA 前将原运行分区和分区元数据备份至工作区 `backup/p4-before-review-SQbppL9A`。OTA 后串口和 TCP 握手正确报告 480×800、`usbOnly=false`，GT911 就绪，Wi-Fi 恢复，带 Origin 的 `/line` 请求返回 403；用户确认亮度、方向和触摸反馈正常，诊断也记录到了触摸事件。两次 TCP 重连及对应诊断查询成功。按键录音实测已完成上传和识别，设备截图确认草稿文字显示；一次向 WorkBuddy 提交在辅助功能读取窗口阶段失败，不能认定消息已送达，也不能仅凭错误确定权限配置就是根因。

### 本地模型对话的执行声明

`pc/src-tauri/src/persona_llm.rs` 为降低本地小模型延迟而跳过桌面工具和回复决策契约，只靠提示词要求模型说明功能不可用。模型仍可能错误声称已派发任务，不能作为执行凭据；需要设计不引入原有高延迟的输出校验和真实执行回执。相关隔离测试的本地服务器因等待第二次请求而卡住，暂不能据此认定该功能通过。
