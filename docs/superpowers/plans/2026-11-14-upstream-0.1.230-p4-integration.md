# Upstream 0.1.230 P4 Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Selectively integrate upstream 0.1.230 runtime improvements into the Waveshare ESP32-P4 port without replacing its Wi-Fi transport, P4 firmware image, or device-side confirmation flow.

**Architecture:** Keep the port branch authoritative for device protocol and interaction rules. Adopt upstream changes only at stable boundaries: Codex terminal-session metadata, serial baud negotiation, and catalog validation allocation. Treat DeepSeek's upstream patch as a reference implementation because this branch already uses the visible-composer route and differs in confirmation semantics.

**Tech Stack:** ESP-IDF C, Rust/Tauri, Node.js, React session transport, pytest, Node built-in test runner, Cargo tests.

**Spec:** Upstream commits `6407092`, `2cb87ec`, `8d4752e`, and `7bd9fd9` from `upstream/main`.

## Global Constraints

- Do not import upstream release notes, installers, or r180/r181 firmware binaries; retain the r183 P4-V3 image.
- `reply_complete` is a device-visible terminal state with the existing 60-second deadline and no completion audio cue.
- Serial discovery must open a supported baseline baud once, then switch rate on the existing handles; it must never replay an application command.
- Boot catalog validation must use unpublished scratch memory and preserve publish-on-success semantics.
- Keep P4 voice drafts confirmed by the existing joystick rules; do not replace them with automatic desktop submission.

## Review Focus

- A terminal Codex reply containing no mutating work must remain visible until its original deadline.
- A Codex turn with a real completed file/image/mutating tool action must retain the existing `done` state.
- A macOS serial driver that rejects 4 Mbaud during open must still discover a board at a fallback baud without reopening the device.
- Unsupported baud changes must not discard buffered bytes belonging to the next protocol frame.
- A failed catalog parse must never publish or mutate the live component runtime.
