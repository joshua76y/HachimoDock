# P4 Wi-Fi 形象传输与连接路由选择设计

## 意图

ESP32-P4 是已完成 USB 首次配对的受控内网辅助终端。用户希望在 Wi-Fi 下安装或切换宠物形象与 USB 一样自动完成；日常自动连接则优先使用 USB，但在两种链路都存在时可由用户明确切到 Wi-Fi，也能随时切回 USB。

## 已确认的现状与根因

- Wi-Fi 形象同步已经会自动开始，`asset/begin` 和 `asset/raw-chunk` 的 ready 回执也成功。
- 桌面端随后按 USB 的协议写入原始二进制块；P4 的 TCP 接收器只组装换行分隔的 JSON，二进制没有被交给 raw-asset 消费器，因此首块等待 ACK 超时。
- 已有 JSON/Base64 `asset/chunk` 协议和 20,478 字节分块；Base64 后加 JSON 元数据仍小于 TCP 端 30 KiB 单行上限。
- 现有后台自动连接把保存的 TCP 路由置于 USB 扫描之前，且当前面板只有“Wi-Fi 直连”和“重新扫描串口”两个操作，不能表达用户的路由意图。

## 目标

1. USB 继续使用原始二进制形象分块，保留现有速度与可靠性策略。
2. TCP/Wi-Fi 自动选择 JSON/Base64 形象分块，使宠物安装及切换自动完成。
3. 桌面端保存一个路由偏好：`auto`、`usb`、`tcp`。
   - `auto`（默认）：扫描已配对 USB；成功即使用 USB；没有 USB 才连接已保存并经身份校验的 TCP 端点。
   - `usb`：只连接 USB，不自动回落到 Wi-Fi。
   - `tcp`：只连接已保存且身份校验通过的 Wi-Fi 端点，即使 USB 已接入也不抢占。
4. 状态栏显示一个清晰的三态手动切换控件；切换立即断开旧链路并连接目标，成功后保存偏好。
5. 无论哪一种偏好，Wi-Fi 仍必须使用既有 `boardDeviceId` 校验；不新增网络握手、密钥或包级认证。

## 非目标

- 不改变首次 USB 配对限制、绑定文件中的设备身份，或 Wi-Fi 音频/语音通道。
- 不修改 P4 固件 TCP 接收器，不强迫用户重新烧录。
- 不支持同时维护 USB 和 TCP 两条控制连接；控制面始终仅有一条活动链路。

## 方案比较

1. 修改 P4 TCP 接收器以识别原始二进制：可复用 USB 快速协议，但须处理 TCP 收包边界、原始流和 JSON 行切换，风险大且要求 OTA。
2. **按链路选择既有编码（采用）**：USB 用 raw；TCP 用 JSON/Base64。无需固件变更，符合现有 TCP JSONL 接收模型，Wi-Fi 传输会比 raw 大约三分之一但可用。
3. TCP 也保持 raw 并在桌面侧重试：不能修复接收器从不消费二进制的根因。

## 验收

- TCP 形象同步日志显示 `json-base64-v1`，不会再出现 raw chunk ACK 超时；USB 仍显示 `uart-raw-v1`。
- 默认自动模式在 USB 存在时连 USB；USB 不存在时连保存的、身份匹配的 Wi-Fi 端点。
- 在 USB 存在时，用户可点选 Wi-Fi 并保持 Wi-Fi；可再点选 USB 立即切回。
- 旧绑定没有路由偏好字段时按 `auto` 处理。
