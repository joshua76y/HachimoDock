# 小智实时问答提供方设计（已被 MQTT + UDP 设计取代）

> 已取代：此稿假设官方 WebSocket 为实时主通道。经官方当前源码和 OTA 实测确认，官方客户端在 MQTT 存在时优先 MQTT，音频采用 AES-CTR UDP/Opus。实施以 `2026-11-18-xiaozhi-mqtt-udp-realtime-design.md` 为准；本文件仅保留决策历史。

## 目标

在 HachimiDock 的实时对话设置中加入第三种提供方「小智 AI」。它以小智的云端实时会话提供较低延迟的中文语音问答，同时继续使用当前 ESP32-P4 固件、USB/Wi-Fi 传输、设备屏幕、按键和宠物 UI。

现有「API」与「OMLX」路径必须保持原有行为和配置隔离。小智第一版不获得 WorkBuddy、Codex、Claude、智能家居、待办、音乐或任意本地工具权限。

## 已确定的范围

- 小智模式是一个完整的实时语音后端：小智完成 ASR、推理、TTS；HachimiDock 只负责安全地桥接音频、状态、字幕与取消。
- 用户在客户端选择小智后，使用小智账号/设备激活取得的配置；凭据只保存在本机加密配置中。
- 继续支持 USB 优先、Wi-Fi 回退的现有设备连接机制。
- 保留小智返回的识别字幕和逐句 TTS 字幕，并映射到现有设备 HUD。

## 明确不做

- 不刷写或替换当前 ESP32-P4 固件，也不复用小智的板级实现。
- 不向小智云端转发当前桌面 Agent、宠物资料、会话记录、家庭设备、API/OMLX 凭据或 PC 文件。
- 不实现小智 MCP 到现有 Agent/本地工具的桥接。
- 不承诺小智官方免费服务的永久可用性、额度或 SLA。

## 方案比较

1. **PC 协议桥接（选择）**：PC 将当前 16 kHz PCM 编为 Opus，经小智 WebSocket 发送；接收小智的 Opus、STT、TTS 状态并解码回当前播放链路。保留现有固件与 UI，新增范围集中且可独立开关。
2. **直接移植小智 ESP32 固件**：小智确实有 ESP32-P4 支持，但会替换本项目的固件、页面、组件、无线绑定和 Agent 功能；不符合“第三种提供方”的目标。
3. **自建小智兼容服务器**：可控性更强，但增加服务器运维，并且仍需自行承担模型、ASR、TTS 和联网成本；不适合本阶段。

## 协议与架构

```text
P4 固件 -- PCM 16 kHz --> HachimiDock -- Opus/WebSocket --> 小智服务
P4 屏幕 <-- 字幕/状态 ------ HachimiDock <-- JSON/Opus ------- 小智服务
P4 扬声器 <- PCM 16 kHz ----- HachimiDock <- Opus ------------ 小智服务
```

小智 WebSocket 使用设备身份、持久 Client ID、认证配置和 hello 握手；会话内以二进制 Opus 帧与 JSON 事件传输。PC 端需独立生成并保存一个虚拟小智设备身份，不挪用或伪造 P4 的硬件身份。首次启用必须完成小智要求的账号绑定/激活；失败时在客户端和设备上明确显示原因。

参考：小智 [WebSocket 协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md)、[OTA/激活协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/ota.md)。

## 实现边界

- 新增 `XiaozhiRealtimeProvider`，仅在选择「小智 AI」时创建；API/OMLX 不引用它。
- 新增经过审查的 Opus 编解码依赖；固定输入 16 kHz 单声道，按服务端协商处理下行采样率。
- 会话取消、P4 断开、切换提供方或应用退出时立即发送 abort/关闭连接，并丢弃迟到音频。
- 日志只保存会话阶段、耗时、HTTP/WebSocket 状态码及错误类别；不记录音频、转写文本、认证令牌或小智设备身份。
- 设置页展示：未配置、待激活、连接中、就绪、失败五种状态；保存后提供无音频的握手测试。

## 验收标准

1. 在不改动 P4 固件的前提下，可经 USB 和 Wi-Fi 完成小智单轮问答、字幕与语音播放。
2. 取消、按键结束、掉线和切换提供方不会残留播放或影响 API/OMLX 的下一轮会话。
3. API 与 OMLX 的自动化测试及现有配置仍通过；小智凭据绝不出现在日志、前端状态或导出的诊断文件。
4. 设备未激活、鉴权失败、网络失败或音频协商失败均有可操作错误提示。

## 实施前验证

先做一次一次性的兼容性验证：使用独立虚拟身份请求小智的激活/会话配置，并建立不发送用户音频的 WebSocket hello。只有官方服务接受这种 PC 桥接身份、并能完成绑定后，才进入正式集成；若官方仅接受其固件生成的身份，则暂停并改评估自建兼容服务。
