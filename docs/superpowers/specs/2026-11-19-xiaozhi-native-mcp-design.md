# 小智原生 MCP 桌面任务派发设计

## 目标

在“小智 AI”实时对话引擎中，让用户以自然语音提出电脑操作、代码、文件或应用任务时，小智云端模型可调用 HachimiDock 提供的 MCP 工具，将**本轮用户已识别的原话**派发给设备当前跟随的 Codex 或 WorkBuddy 对话。

该能力复用已验证的 `desktop_agent` 输入、去重、回执与权限链路；小智负责高质量实时理解和语音回答，目标桌面 Agent 负责实际执行。

## 非目标

- 不改动 API / 本地 OMLX 实时对话路径、既有 Agent 跟随逻辑或固件。
- 不新建小智控制台的外部 MCP 端点、不启动第二个桥接进程、不保存控制台端点凭据。
- 不开放任意系统命令、文件系统、付款、授权或绕过目标 Agent 的确认机制。
- 首版不把桌面 Agent 的异步最终结果主动插话播报；用户可继续问“进度怎样”或“结果是什么”。

## 采用方案

采用小智的**原生设备 MCP**：HachimiDock 已作为虚拟小智设备维持 MQTT + UDP 会话，因此客户端同时担任 MCP Server。小智云端网关作为 MCP Client，在 MQTT 控制主题中完成发现、工具目录读取与调用；UDP 仍只传音频。

未采用“云端扩展 MCP”：该方案需要额外启动本机 MCP 服务并连接小智智能体的私有 WebSocket 端点，运维、凭据与失联状态更多，且与当前已稳定的 MQTT 会话重复。

## 用户可见设计

在 PC 客户端“小智 AI”配置区增加独立开关：`允许小智派发桌面任务`，默认关闭。开启后显示“将派发到当前跟随的 Agent（Codex 或 WorkBuddy）”。

开关关闭时，客户端继续以 `mcp: false` 连接，原有小智问答行为不变。开启后，下次建立小智会话时才宣告 MCP 能力；若当前会话存在，客户端提示重新进入实时对话后生效。该设置与 API / OMLX 的 Agent 能力完全隔离。

## 连接与协议

1. 设置保存后，OTA 能力声明与 MQTT `hello.features` 一致地报告 `mcp: true`。
2. 小智网关连接后可发送现代 `server/discover` / `tools/list`，或旧版 `initialize` / `tools/list`。
3. 客户端实现两种官方兼容格式，并在 MQTT `type: "mcp"` 包裹的 JSON-RPC 2.0 中回复；不记录原始 payload、语音内容或凭据。
4. 对话期间仅接受当前 session 的 `tools/call`；请求 ID 保持原类型回传。未知工具、非法参数、过期会话和重复调用均给出结构化 MCP 错误或 `isError` 结果，不重试有副作用的调用。

## 工具目录

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `desktop_agent.dispatch` | 无 | 仅以本轮刚收到的最终 STT 原文创建任务，派发到当前跟随的 Codex 或 WorkBuddy。 |
| `desktop_agent.status` | 可选 `taskId` | 返回本设备、当前跟随 Agent 最近任务或指定任务的状态。 |
| `desktop_agent.result` | 可选 `taskId` | 返回可核对的完成摘要；未完成时只返回当前状态。 |

首版不提供 `cancel`。取消属于副作用且容易被语音上下文中的歧义指令误触发，仍由用户在目标 Agent 内处理。

## 授权、绑定与去重

- `dispatch` 不接受云端模型提供的任务文本，也不让模型改写任务；只绑定当前小智会话中最新、未消费、长度受限的最终 `stt` 事件。
- 若没有新鲜的用户原话、该原话已派发过、当前跟随目标不是 Codex/WorkBuddy，或实时会话已结束，调用失败且不会写入任何桌面输入框。
- 用现有 `desktop_agent::Context` 构造派发上下文，继承同一会话/设备/当前跟随目标、输入框预检、请求散列和不确定投递不自动重试的规则。
- 每个工具调用及其任务状态均受当前小智 session 和本地 HachimiDock 会话绑定；别的设备或旧会话不能查询、执行或复用。

## 语音与状态流

```text
用户语音 → 小智 STT（客户端保存最终原话）
         → 小智模型决定调用 desktop_agent.dispatch
         → HachimiDock 用保存的原话派发到当前跟随 Agent
         → MCP 工具结果回给小智模型
         → 小智用其原生语音说明“已交给 Codex / WorkBuddy”或失败原因
后续用户询问进度/结果 → status / result → 小智原生语音回答
```

客户端屏幕继续显示小智原本的识别与回复字幕。诊断日志只记录工具名、操作、成功与否、耗时、任务 ID 类型及固定错误类别；不记录任务正文、模型工具参数、转录或音频。

## 失败处理与验证

- MCP 发现或目录读取失败不阻断小智正常语音聊天；工具仅不可用。
- 工具执行失败只返回一次错误结果，不会自动重派发。
- 测试覆盖现代与旧版发现、目录、无新鲜 STT 的派发拒绝、重复调用、错误会话、Codex/WorkBuddy 目标选择、status/result 及隐私日志过滤。
- 物理验收：开启后重新进入小智对话，说一个明确桌面任务，确认目标 Agent 收到；再分别询问任务进度与结果；关闭开关后确认工具不再出现且小智问答不受影响。
